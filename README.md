# game-bot

MAX-бот АНО «Агентство развития игровой индустрии» с регистрацией участников, заявками на мероприятия/стажировки/команду и игрой «Жизнь».

## Главное

- единый профиль участника: ФИО → контакт MAX → учебное заведение;
- после регистрации ФИО, телефон и учебное заведение больше не спрашиваются;
- при вступлении в команду, записи на мероприятие и стажировку человек выбирает только то, чем хочет заниматься или что ему интересно;
- мероприятия хранятся в таблице `events`, поэтому дата, место, описание и набор интересов больше не зашиты в обработчики бота;
- рейтинг игроков и рейтинг учебных заведений;
- игра «Жизнь» с двумя режимами: быстрым и полным.

## Регистрация

При первом запуске бот не показывает основное меню, пока пользователь один раз не заполнит профиль:

1. ФИО;
2. номер телефона через системную кнопку `Поделиться контактом MAX` — вручную вводить номер не нужно;
3. учебное заведение.

Для популярных вузов Уфы есть готовые кнопки. Свободный ввод нормализуется в `institution_key`, поэтому варианты вроде `УГНТУ` и `Уфимский нефтяной университет` попадают в одну группу рейтинга.

Персональные данные хранятся в `users`. Новые записи `applications` больше не дублируют ФИО, телефон и учебное заведение — заявка содержит ссылку на пользователя, тип, интересы и код мероприятия. Старые данные остаются совместимыми и используются для автоматического заполнения существующих профилей.

## Мероприятия

Открытые события берутся из таблицы `events` и автоматически появляются в главном меню. Для события хранятся:

- `code`;
- название;
- дата и время;
- место;
- описание;
- доступные интересы/активности;
- статус регистрации.

Текущее мероприятие `party-2026-09-18` автоматически создаётся/обновляется из переменных окружения при старте приложения. Следующие события можно добавлять в `events` без переписывания обработчиков меню и регистрации.

## Игра «Жизнь»

Основная библиотека содержит **468 сценариев**: 9 возрастных этапов × 13 тематик × 4 варианта ситуаций. Дополнительно работают:

- 10 профессиональных траекторий;
- 40 специализаций;
- 120 специализационных карьерных событий;
- многолетние цели;
- долгосрочные проекты;
- вероятностные проверки;
- постоянные NPC и отношения;
- энергия и ограниченное время;
- последствия привычек;
- денежный журнал.

### Два режима

`⚡ Быстрая жизнь` — около 16 ключевых решений от 16 до 60 лет. Между ключевыми возрастами игра может перескакивать несколько лет и суммирует обычную экономику периода.

`🧭 Полная жизнь` — один ход на каждый год, 44 решения от 16 до 60 лет.

### Прозрачные последствия

Прямые деньги видны **до выбора** прямо на кнопке:

```text
🎓 Готовиться к вузу · 💸 5 000 ₽ · ⏱ 2
💼 Искать первую работу · 💰 +18 000 ₽ · ⏱ 1
```

Каждый прямой эффект получает отдельную причину. Для всех 468 сгенерированных сценариев CI проверяет, что изменения показателей имеют объяснение, а прямое изменение денег показывается до выбора.

После решения бот показывает короткий результат, например:

```text
✅ Ты начал готовиться к поступлению.

🧠 Навыки +8 — регулярная подготовка дала больше практики.
😰 Стресс +4 — к обычной учёбе добавились дополнительные занятия.
💰 Деньги -5 000 — учебные материалы и пробные тесты.
⭐ Очки: +84 → 3030
```

Технические блоки вроде «профессия ещё не выбрана, экономика не рассчитывается» больше не показываются. Если автоматическая экономика действительно применялась, она доступна в подробном расчёте.

Кнопки после хода:

- `➡️ Следующий этап`;
- `📋 Подробнее о расчёте`;
- `📊 Показатели`.

`📊 Показатели` больше не переводит игру на следующий год — это отдельный экран состояния.

### Один игровой движок

Полный ход теперь рассчитывается внутри `src/game/engine.js`: решение, шанс, NPC, проект, цель, экономика, привычки, энергия, время, долг, очки и переход возраста. Бот отвечает только за отображение и сохранение результата.

Это устраняет ситуацию, когда часть механик считалась в движке, а энергия — отдельно в `bot.js`.

### Энергия и время

У игрока есть `⚡ энергия` 0–100 и базово 4 единицы времени. Работа, активный проект, высокая карьерная ответственность и близкие отношения занимают часть периода. Выбранное действие стоит `⏱ 1–3`.

Перегрузка снижает энергию, повышает стресс и при истощении влияет на здоровье. Низкая энергия также уменьшает доступное время и шанс рискованных действий.

### Привычки

Вредная привычка теперь имеет понятные состояния:

- нет;
- разовый эпизод;
- эпизодическая;
- регулярная;
- зависимость.

Разовая проба не создаёт выдуманных регулярных расходов. Если эпизод не повторяется, риск постепенно снижается. Расходы и долгосрочный вред появляются только при закрепившейся привычке.

### Денежный журнал

Игра сохраняет последние денежные операции: прямые расходы/доходы решения, обычную экономику периода, проектные награды, последствия привычек и появление долга. Журнал доступен на экране показателей.

## Карьера

В 19 лет выбирается широкая профессиональная среда, в 20 — профессия, в 22 — специализация.

Профессии:

- 🎮 разработка игр;
- 💻 IT;
- 🧪 нефтехимия;
- ⚙️ инженерия;
- 🩺 медицина;
- 📚 педагогика;
- 🎨 дизайн и медиа;
- 🚀 предпринимательство;

У каждой профессии 4 специализации и отдельная должностная лестница.

## Автоматическая проверка баланса

Добавлен симулятор массовых прохождений:

```bash
npm run balance
```

По умолчанию он прогоняет 2 000 жизней для нескольких стратегий и выводит:

- средний/медианный итоговый балл;
- p10 и p90;
- средние деньги и долг;
- долю игроков с долгом;
- здоровье, счастье, стресс и энергию;
- долю прохождений с истощением;
- среднюю карьеру и число ходов.

Можно менять режим и количество прогонов:

```bash
npm run balance -- --runs=10000 --mode=classic
npm run balance -- --runs=10000 --mode=quick
```

## Проверки

```bash
npm run check
npm test
npm run balance -- --runs=500 --mode=quick
```

CI проверяет синтаксис, полный проход игры, сценарии, карьеру, специализации, цели, проекты, NPC, энергию, вероятности, прозрачность причин эффектов, предварительное отображение прямых расходов и быстрый режим.

## Production

Сейчас бот работает через Long Polling. Для production рекомендуется HTTPS Webhook с проверкой secret. Перед публичным сбором персональных данных нужно заполнить реальный `PRIVACY_URL`.
